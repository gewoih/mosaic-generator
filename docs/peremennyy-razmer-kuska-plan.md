# Переменный размер куска: крупнее на фоне, мельче у деталей

План к пункту 8 из [`TODO.md`](../TODO.md). Аргументация до правки — по конвенции проекта
для исследовательских изменений.

---

## 1. Что не так сейчас

Длина откуса (`ModuleAlongMm`) — одна на всё панно. `Tessellation.Advected` делит каждый
курс на куски с постоянным шагом `dAlong = along + grout` (`AddSites`). Открытое небо и
спокойная вода набираются тем же куском, что и оперение или кромка хребта.

Мозаичист так не работает. На ровном фоне куски крупнее, у деталей мельче — это и делает
набор живым, а не машинным, и физически дешевле: крупный кусок на спокойном поле не несёт
информации, дробить его незачем.

## 2. Почему это стало простой правкой

После перехода на прямоугольный кусок поперечная сторона закреплена толщиной плитки
(`ModuleAcrossMm`, 7 мм). Менять надо ровно **одну** величину — шаг деления курса.
`ModuleChoice` уже отдаёт `ModuleAlongMm` и `ModuleAcrossMm` раздельно
(`Domain/ModuleSelector.cs`), ядро к этому готово.

Ограничение из ремесла: размер меняется **между** курсами, а не внутри одного — в ряду
куски держат общую длину, шов остаётся постоянным. Это выходит само, если трогать только
`along`: `across`, `dAcross`, `maxTurn`, шов (`GroutFor` считает его от `across`) не
затрагиваются.

## 3. Решение

### 3.1. Сигнал — сила края

`DirectionField` уже строит карту силы края (`_edge`, 0..1 до диффузии) и целиком
передаётся в `Advected`. Среднее `field.EdgeAt` вдоль курса отвечает на нужный вопрос:
курс идёт через спокойное поле или через занятое.

**Почему не дисперсия цвета** (как в наброске 4G, [`andamento-fon-plan.md`](andamento-fon-plan.md) §4):
её расчёт требует протащить `SourceImage` + `CropRect` в код, который сейчас видит только
поле направлений. Это заметно больше связей ради сигнала второго порядка. Добавим отдельно,
если замеры покажут, что ровные, но пёстрые зоны (галька, листва) остались крупными.

**Почему не когерентность поля**: `DirectionField.CoherenceAt` уже идёт в `Guide` при
смешивании эха контура и текстуры — её смысл частично дублируется.

### 3.2. Размер — дискретный, из ряда {6, 8, 10, 12, 15, 20} мм

Тот же ряд, из которого `ModuleSelector` выбирает базовый откус. У мастера не континуум
размеров, а несколько; куски в реальных размерах читаются как осознанные, произвольные
9,3 мм — нет. Пункт 4 (честная строка «столько-то кусков такого-то размера») тоже требует
называемых размеров. Геометрически стабильнее: 2–3 чётких размера вместо смаза.

`ModuleAlongMm` остаётся базовым — это минимальный, детальный размер; курсы шагают вверх.

### 3.3. Максимум — до 1.7× базы

Цифра из `andamento-fon-plan.md` §4 («крупные 10–15 мм на фоне, средние 7–10 мм на
фигуре»). При базе 6–8 мм фон выходит 10–13 мм.

- 1.4× — почти не читается, один шаг ряда;
- 2.0× — обостряет щель на концах курсов (пункт 5, сейчас худшая открытая проблема),
  плохо смотрится на изогнутых фоновых курсах;
- **1.7×** — замеренная середина; при снапе к ряду 1.7·6 = 10.2 → 10, 1.7·8 = 13.6 → 12.

### 3.4. Отображение

Один раз в `Advected`: `edgeRef` = порог контура, как в `ContourSet`
(`strong = Percentile(field.EdgeCells, 0.99); edgeRef = max(0.12, strong · 0.42)`) —
привязка к тому же уровню, по которому строятся контуры, без нового параметра.

Для курса:

```
e     = среднее field.EdgeAt(x/W, y/H) по вершинам полилинии
t     = clamp(e / edgeRef, 0, 1)
scale = 1.7 − 0.7 · t          // t→0 ровно → 1.7 ;  t≥1 деталь → 1.0
localAlong = ближайшее значение ряда к (along · scale) в [along, along · 1.7]
             при равенстве — меньшее (как «более мелкий выигрывает» в ModuleSelector)
```

Применяется **только к заливочным линиям тока** (этап 3). Бордюр, контурные курсы
(opus vermiculatum, этап 2) и одиночные заплатки (этап 5) остаются базовым `along` —
структурные элементы и патчи, их размер не гуляет.

## 4. Где правится

Вся правка — `src/MosaicGenerator.Core/Grid/Tessellation.cs`, метод `Advected`:

| Место | Изменение |
|---|---|
| `AddSites` | флаг «можно менять размер»; для заливки считает `localAlong`, использует `localAlong + grout` для числа точек и `localAlong · 0.6` для отступов от концов |
| site-кортеж `(Centre, Tangent, CourseId, Index)` | + `double AlongMm` |
| `CutCells` | `boundAlong` и `fullArea` для `Finish` — из `site.AlongMm`; `reach = max(along · 1.7, across) · 2` |
| `MergeSlivers` | `floorAlong = max(site.AlongMm · 0.5, floorAcross)` |
| этапы 1–2, одиночки этапа 5 | вызов `AddSites` с флагом «не менять» |
| новый хелпер | снап к ряду `{6, 8, 10, 12, 15, 20}` |

Не трогается: `ModuleChoice` / `ModuleSelector`, `MosaicLayout`, web-слой, рендер, расчёт
материала. `JointOptics.ModuleFraction` останется приближением (одно на панно) — на
восприятие цвета влияет слабо.

# Что вышло

Сделано 2026-09-02. Вся правка — в `Tessellation.Advected`.

## Что изменилось в коде

- site-кортеж получил поле `AlongMm` — длину откуса своего куска;
- `AddSites` для заливочных курсов (этап 3) считает `courseAlong` через `ResizedAlong`:
  среднее `field.EdgeAt` вдоль курса задаёт `t = clamp(e / (edgeRef·0.35), 0, 1)`
  (полный масштаб уже там, где край втрое слабее контурного — большая часть неба и
  спокойной воды), `scale = 2.0 − 1.0·t`; **плюс ворота по прямизне** — `chord/arc`
  курса: полный масштаб выше ~0.95, ниже 0.80 растяжки нет вовсе. Длинный жёсткий
  кусок не идёт по дуге, поэтому изогнутый фоновый курс (эхо силуэта, угол поля)
  остаётся базовым откусом даже на ровном тоне. Итог снапится к ряду {6,8,10,12,15,20};
- `edgeRef` = порог контура (`ContourLevel`, зеркалит `ContourSet`); при отсутствии
  контуров вообще размер не гуляет;
- `CutCells` берёт `boundAlong` и `fullArea` из `site.AlongMm`, `reach` расширен до
  `max(along·1.7, across)·2`; `MergeSlivers` — `floorAlong` из `site.AlongMm`;
- бордюр, контурные курсы и одиночки этапа 5 — базовым `along`.

## Глазами

Превью до/после в `images/peremennyy-razmer/`. Небо чайки и вода дельфина в спокойных
зонах — куски крупнее; концентрические дуги вокруг фигуры и сама фигура — базовым
размером; переход плавный, резких скачков между соседними курсами нет. На пейзаже
дальнее небо заметно крупнее переднего плана — то, ради чего пункт и делался.
