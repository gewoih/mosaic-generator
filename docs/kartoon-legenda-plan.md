## Проблема (из бэклога)

Картон печатается без легенды, кодов, контура панно и масштабной линейки. Пользователь
определяет артикул на глаз по цвету картона и сверяется с экраном — это работает, пока
10–15 артикулов различимы **на печати**, а сейчас ничто этого не гарантирует. Плюс на листе
нет ни контура панно, ни линейки, чтобы проверить масштаб печати.

## Что делаем и что нет

| Подпункт п. 7 | Решение этого плана |
|---|---|
| 1. Полоса легенды на самом картоне | делаем: плашка артикула + код + число кусков, за пределами поля мозаики |
| 2. Контрольная линейка 100 мм и контур панно | делаем |
| 3. Гарантия различимости (ближе некоторого ΔE) | **только предупреждение в вебе**, раскладку не трогаем |
| 4. Коды в каждой тессере не нужны | уже так, ничего не делаем |

Подпункт 3 сознательно ограничен предупреждением: автослияние в свёртке меняет раскладку,
а урок пункта 9б — «любое возмущение выше по пайплайну перекидывает целую полосу тессер».
Правка отрисовки такого риска не несёт. Если предупреждение окажется полезным и частым —
автослияние станет отдельным пунктом бэклога со своей аргументацией и замером дна ΔE.

## Компоновка листа (выбрано: нарастить холст)

Панно рисуется как сейчас — пиксель-в-пиксель, тот же `PixelsPerMm`. Вокруг добавляется
белое поле листа: узкое сверху и по бокам (6 мм) — только чтобы контур панно было где
провести, и широкий подвал снизу под линейку и легенду. Весь холст несёт один `pHYs`,
поэтому при печати «100 %» и панно, и линейка выходят в реальный размер.

```
┌─────────────────────────────┐  ← лист (белый)
│ ┌─────────────────────────┐ │  ← контур панно (тонкая рамка по истинному краю)
│ │      поле мозаики        │ │
│ │   (панно как сейчас)     │ │
│ └─────────────────────────┘ │
│                             │
│ ├──────100 мм──────┤        │  ← линейка с делениями через 10 мм
│                             │
│ ▪ SM-01 ×842   ▪ SM-07 ×310 │  ← легенда: плашка, код, число кусков
│ ▪ SM-02 ×511   ▪ SM-09 ×205 │     колонки по ширине панно
└─────────────────────────────┘
```

Все размеры подвала заданы в миллиметрах и переводятся в пиксели через `PixelsPerMm`:
поле листа 6 мм; линейка 100 мм длиной, деления 10 мм (длиннее на 0/50/100), подпись
«100 мм»; плашка легенды 8×8 мм; ячейка легенды ~44 мм шириной, строка ~13 мм;
шрифт — высота прописной ~4 мм, гарнитура `SchemeFont` (та же, что у схемы). Число
колонок = `floor(ширина панно / ширина ячейки)`, минимум 1; строк — сколько нужно.

## Изменения в коде

### Ядро — геометрия подвала (новый, без графики)

`Core/Rendering/CartoonSheet.cs` — чистая математика, тестируется напрямую:

```csharp
public static CartoonSheet Layout(RenderPlan plan, MaterialReport report);
```

`CartoonSheet` содержит: размер всего листа в пикселях; смещение панно `PanelOffsetPx`;
прямоугольник контура; геометрию линейки (начало, длина в пикселях = `100 * PixelsPerMm`,
позиции делений, точка подписи); список ячеек легенды (прямоугольник плашки, точка кода,
`ColorIndex`, код, `ModuleCount`) — по строке на `report.Lines` в их порядке (уже по
числу кусков убыв.).

Держим в `Core/Rendering` рядом с `RenderGeometry` и `RenderPlan`; `RenderGeometry` не
трогаем — подвалу нужен `MaterialReport`, а он появляется только в рендерере.

### Ядро — рендерер

- `IMosaicRenderer.RenderCartoon(RenderPlan)` → `RenderCartoon(RenderPlan, MaterialReport)`,
  как у `RenderScheme`.
- `SkiaMosaicRenderer.RenderCartoon`: считает `CartoonSheet.Layout`, аллоцирует битмап
  размером листа, заливает белым, рисует панно со смещением `PanelOffsetPx` (как сейчас,
  но со сдвигом canvas), проводит контур, рисует линейку и легенду. Вёрстка — из
  `CartoonSheet`, здесь только отрисовка примитивов.
- Плашка легенды — цветом артикула с картона (`line.Color.Lab.ToRgb().Clamped()`), тем же,
  что заливка тессеры.

### Ядро — различимость (новый, тестируемый)

`Core/Material/PaletteLegibility.cs`:

```csharp
public const double MinPrintDeltaE = 5.0;
public static IReadOnlyList<ConfusablePair> ConfusablePairs(
    IReadOnlyList<MaterialLine> lines, double threshold = MinPrintDeltaE);
```

`ConfusablePair(string CodeA, string CodeB, string ArticleA, string ArticleB, double DeltaE)`,
отсортированы по `DeltaE` возр. ΔE — `ColorDistance.CieDe76` по `line.Color.Lab` (Cie76, как
прод). Порог 5: ниже пяти ΔE два соседних куска на панно уже читаются как одно поле
(`ColorDistance.NeighbourFalloff` — тот же порог и та же причина), значит на печати их плашки
тем более не различить. Если предупреждение будет срабатывать шумно — порог поднять; это
дешёвая правка, потому что раскладку он не трогает.

### Ядро — сервис и результат

- `MosaicGenerationService.Generate`: новый вызов `RenderCartoon(cartoon, report)`.
- `MosaicResult`: добавить `int CartoonSheetWidthPx`, `int CartoonSheetHeightPx` (из
  `CartoonSheet.Layout`) — чтобы подпись под картинкой в вебе показывала реальный размер
  листа, а не только панно.

### Веб

- `MosaicController.Describe`: `CartoonWidthPx`/`CartoonHeightPx` заполнять размером листа;
  добавить `Confusable` — `PaletteLegibility.ConfusablePairs(result.Report.Lines)` в
  `StoredResult` (список короткой записи, сериализуется во временное хранилище).
- `Views/Mosaic/Result.cshtml`:
  - если `Confusable` непустой — блок предупреждения: «Коды X и Y почти неотличимы на
    печати (ΔE N): проверьте по экрану или закрепите один и уберите второй лимитом цветов».
  - переписать устаревшую подпись (**заодно TODO п. 11**): «набранное панно сядет чуть
    глуше картона» — компенсацию шва выпилили, шов рисуется прямо на картоне. Оставить
    только фразу про физический масштаб и добавить, что картон теперь самодостаточен —
    легенда на листе.

### Стенд

`tools/MosaicGenerator.Diag/Program.cs` — только протянуть сигнатуру
`RenderCartoon(cartoon, report)`. Картоны в `diag-out/` получат тот же подвал: правило
«смотреть глазами» получает тот же артефакт, что и пользователь.

- `dotnet test` зелёный;
- прогон стенда по всем `samples/` на 21×21, A4, 40×40 (воротные — плюс 60×60):

  линейкой в 100 мм при печати 1:1, контур точно по краю панно, плашки легенды
  различимы между собой.
- проверить предупреждение о различимости на реальной палитре ArtWorker при 12 и 15
