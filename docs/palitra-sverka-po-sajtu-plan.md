# Сверка палитры со вторым источником — artworker.shop (план)

## Зачем

Сверка по вееру (`palitra-sverka-po-veeru.md`, `b4dc27b`, сегодня) исправила шесть
артикулов, но у неё есть слепая зона: стопки, где белые/светлые плашки сливаются с
бумагой (`TJ01…SX42`, `GX02…SS15`), размечались кропами глазами, и `SX42` стоит
последним в белой стопке. Пользователь заметил на сайте: `SX42` в JSON — «Серый»
`#8B8486`, а на витрине магазина это отчётливо фиолетовый (лавандово-сиреневый).
Значит замер по вееру для `SX42` схватил край бумаги/соседнюю белую плашку.

Нужен **независимый второй источник HEX**, чтобы поймать такие грубые промахи
(нейтраль ↔ хроматика), а не только шум ±3 dE.

## Что даёт сайт (разведка проведена)

Магазин на InSales. **HEX на сайте нигде не публикуется.** Доступно два сигнала:

1. **Атрибут «Цвет»** на карточке товара — грубое русское имя категории
   («Фиолетовый», «Серый», «Синий», «Голубой», …). Для `SX42` там стоит
   **«Фиолетовый»** — прямое противоречие нашему «Серый». Годится как грубый
   классификатор тона, не как HEX.
2. **Фотографии товара.** Для большинства артикулов есть SKU
   «Смальта XX, колотая 10х17 мм, 200 гр» — колотые кусочки в стеклянной банке
   на сером выветренном дереве. Это **самый ровный цветовой образец на сайте**:
   матовая масса кусочков, много площади, проверено — снимки поколоночные, не сток
   (`FP20` синий, `SX42` лавандовый). Плашки 91×91 — хуже: сняты под углом, бликуют.

   URL картинок: `https://cdn.insales-shop.ru/.../images/products/1/<id>/<id>/NN.jpg@jpg`,
   можно взять полноразмерную (`rs:fit:1000`).

Ограничения источника, которые нужно держать в голове:

- У снимков холодный дневной свет + подсветка от серого дерева → общий холодный
  увод. Абсолютный HEX будет приблизительным (±5–8 dE), годным для отлова грубых
  промахов, **не** для тонкой подгонки на 2–3 dE.
- Гланец на отдельных кусочках. Лечится медианой по маске.
- Слаги карточек нерегулярные (`smalta-sx42-10h10-mm`, `smalta-sx42-91h91h10-mm`) —
  каждый артикул искать через `/search/?q=<артикул> колотая`.
- Не у всех 152 артикулов есть «колотая» SKU. Где нет — фолбэк на фото плашки
  91×91 (хуже) либо позиция остаётся на замере по вееру.
- ~150 карточек через браузер — медленно. Сбор ссылок на картинки — через поиск
  на сайте; скачивание и разбор картинок — офлайн-скриптом.

## Веер остаётся первичным

Веер — единый кадр, единый свет, 152 образца рядом; сайт — 150 разных снимков в
разном свете. Поэтому: **сайт не заменяет веер, а перекрывает его слепую зону.**
Правим по сайту только там, где (а) веер сам себя пометил ненадёжным
(стопки с белым, блик > четверти плашки), или (б) сайт и веер расходятся по
классу тона (атрибут «Цвет» против нашего имени), или (в) dE(веер, сайт) велик
и картинка кусочков глазами подтверждает сайт.

## Процедура

### 1. Сбор данных с сайта (браузер + скрипт)

Для каждого из 152 артикулов:

- открыть `/search/?q=<артикул> колотая`, перейти в карточку «колотая 10х17»;
  если её нет — карточку плашки;
- записать: атрибут «Цвет», URL полноразмерной главной картинки, тип образца
  (колотая / плашка), `slug`;
- сложить в `docs/data/artworker-site-raw.json` (новый файл:
  `[{article, siteColorName, imageUrl, sampleType, slug}]`).

Картинки скачать в `diag-out/palitra-sajt/<артикул>.jpg` (не в репозиторий).

### 2. Снятие HEX с картинок (скрипт, вне основного solution)

Разовый скрипт `tools/PaletteSiteSampler/` (консоль, SkiaSharp — уже в зависимостях
ядра) либо, если так проще, инлайновый C#-скрипт в `tools/MosaicGenerator.Diag`
под флагом. На вход — папка картинок и `artworker-site-raw.json`.

Для «колотой» (кусочки в банке):

1. Центральный кроп 50 % по ширине и высоте — там гарантированно кусочки, не фон
   и не край банки.
2. Перевод в Lab. Маски-выбросы:
   - блик: L\* > (перцентиль 85 по кропу);
   - тёмная щель между кусочками: L\* < (перцентиль 15);
   - серое дерево, если пролезло: убирается центральным кропом, дополнительно
     отбросить пиксели с C\* < 4 **если** медианная C\* кропа заметно выше
     (не давить хроматику у настоящих серых артикулов — порог по контексту).
3. Медиана оставшихся пикселей в Lab → назад в sRGB → HEX-кандидат.

Для плашки 91×91 — тот же приём, кроп по самой плашке (найти по маске
«не дерево»), медиана 25–75 % / 25–75 %.

### 3. Отчёт (судья — картинка)

`docs/palitra-sverka-po-sajtu.md` (разбор, по образцу веерного) + таблица
`docs/data/artworker-site-compare.csv`:

| article | jsonHex | fanHex(было) | siteHex | dE76(json,site) | siteColorName | jsonName | классТона совпал? | вердикт |

Вердикт выставляется вручную после просмотра картинки кусочков глазами
(`Read` по `diag-out/palitra-sajt/<артикул>.jpg`), приоритет — картинка, не dE.
Кандидаты на правку: класс тона не совпал ЛИБО dE76 > 8 и глаз согласен с сайтом.

### 4. Правка JSON

Только подтверждённые позиции. Для каждой — строка в таблицу «Что нашлось»
с обоснованием (как в веерном разборе). Имена пересчитать по тому же правилу
L\*C\*h из `palitra-sverka-po-veeru.md` для изменившихся HEX.

Шесть белых артикулов (`GX02`, `VB04–07`, …) не трогаем — пункт 19 TODO.

### 5. Перепроверка

- Прогон приёмки (`TODO.md` → «Приёмка», все `samples/`, 21×21, 12 цветов)
  до и после. База ΔE снова сбрасывается — зафиксировать в
  `palitra-sverka-po-sajtu.md` и в `TODO.md`.
- Картоны `poppy`, `gull`, `cat-dusk` (те, что двигались от веерной правки) —
  глазами до/после.
- Отдельно проверить `SX42` на живом кадре (`gull` его использует? если нет —
  синтетический прогон), что сиреневый не поехал в фон.

## Что кладём в бэклог, не в этот проход

- Автоматический парсер витрины при обновлениях палитры — нет, разовая сверка.
- Тон 2–3 dE по сайту — источник не тот, не гонимся.
