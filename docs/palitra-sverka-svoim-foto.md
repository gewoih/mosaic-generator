# Пересъёмка палитры собственным фото веера (2026-09-09)

Предыдущие две сверки (`palitra-sverka-po-veeru.md`, `palitra-sverka-po-sajtu.md`, обе
2026-09-07) работали с чужими фото: промо-снимок производителя и фото банок с витрины
магазина. У обоих источников свои слепые зоны — у первого пересвет, у второго дерево и
тень внутри банки. Пользователь съездил в магазин и переснял тот же физический веер
своей камерой (Sony, RAW/ARW → PNG через Lightroom), это дало полный контроль над
балансом белого, экспозицией и тоновой кривой — то, чего не было ни в одном прежнем
источнике.

## Съёмка: два прохода

Первый экспорт (762/764, оба кадра — веер разрезан на половины, Line 1–4 и Line 5–8)
показал пересвеченный баланс белого и заниженную экспозицию. Скорректировано:
баланс белого — пипеткой по пластику веера (не по бумаге, не по авто), не по показанию
на глаз; экспозиция поднята, пока белая плашка `TJ01` не стала читаться как белая
(была ~140/255, стала ~190–220/255), клиппинг светов не появился.

Второй проход вскрыл обратную проблему: **тени были обрублены S-образной тоновой
кривой** — 22 артикула имели канал, упирающийся в 0. Разобрано отдельно: у части
это настоящий обрыв (нейтральные тёмные — `DK13`, `DK11`, `SK15`), у части — просто
натура насыщенного цвета (у оранжевого синий канал и должен быть у нуля, это не
клиппинг). После честной классификации осталось всего 4 настоящих обрыва тени, три
из них — глубокие сине-фиолетовые (`SQ06`, `SX43`, `SR04`), где красный канал
действительно близок к нулю и после Tone Curve → Linear + Blacks. Точечно
перепроверены крупным планом (`SQ06` — тень падала только на верхний скруглённый
край плашки, не на область замера; `SU06` проверен отдельно по запросу — ровный по
всей высоте, без перекоса, замеру доверять можно).

## Метод замера

- **Границы плашек — по швам, не по цвету.** Ранний подход (маска «не бумага»)
  ломался на светлых первых плашках каждой стопки — грубо промахивался мимо
  посаженных кусков. Рабочий метод: медиана строки по узкой центральной полосе
  колонки, поиск пиков градиента по Lab вдоль столбца — граница между двумя кусками
  видна всегда, независимо от их цвета. Проверено наложением найденных линий на
  исходник по всем 8 колонкам (`kak_meryu.png`, `all_bounds.png` в переписке).
- **Нормировка на бумагу рядом с каждой плашкой**, не на общий уровень кадра: свет
  по кадру гуляет (внизу кадра бумага темнее верха на ~35%), общая нормировка дала
  бы систематический перекос по стопке.
- **Абсолютная привязка — по физическим якорям.** Без серой карты в кадре: белая
  укрывистая смальта принята за отражение 0,82, графитовая — за 0,045 (три самых
  светлых и три самых тёмных артикула по замеру — якоря степенной кривой). Проверка
  сходимости: под этой кривой бумага веера сама выходит на отражение 0,74–0,75 —
  ровно то, что и должно быть у некрашеного картона, не белого листа. Кривая
  поканальная (RGB отдельно), не по яркости — иначе цветность съезжала.

## Что изменилось в палитре

Все 152 HEX переписаны. Средний сдвиг к прежним значениям — dE 9–12, самые крупные:
`GR80`, `GR25` (были кислотно-жёлтыми из-за пересвета у производителя, стали более
глухими золотистыми), `SF15`, `SX23`, `SQ06`, `TF10`, `TW15`, `FC20`, `TC15` — то же
направление, что и обе прежние сверки уже находили (светлый жёлто-зелёный конец
завышен пересветом, тёмный/насыщенный конец занижен). `SX42`/`FN10` — правка
`palitra-sverka-po-sajtu.md` (класс тона: не серый, а сиреневый) подтверждена
независимо: новый замер даёт `SX42 #797275` (R>B>G, тёплый фиолетовый отлив),
`FN10 #D4D0C6` — то же направление, не откат.

Имена не менялись — только HEX; названия уже приведены к правилу L\*C\*h в
`palitra-sverka-po-veeru.md`.

Ревью — четыре листа «фото | сейчас | предлагаю» на все 152 артикула, отправлены
пользователю до записи в файл, одобрены.

## Механизм «похожих цветов» не требует ручного обновления

`PaletteClustering.Compute` (`Core/Domain/PaletteClustering.cs`) пересчитывает
кластеры неотличимых артикулов (полная связка, порог 3,0 ΔE76) заново при каждой
загрузке `artworker-smalt.json` — заранее посчитанного файла-словаря синонимов нет.
Правка HEX подхватывается сама. Единственное следствие для кода — тест
`RealArtWorkerPaletteFoldsTheKnownDuplicates` держал диапазон представителей
136–151, посчитанный на прежних (пересвеченных) HEX; на новых данных получилось 131 —
у настоящей смальты близких пар больше, чем показывало пересвеченное фото
производителя (33 пары с ΔE<3 против прежних непосчитанных). Диапазон в тесте
раздвинут до 120–145, проверка на пятёрку белых (`GX02`/`VB04`/`VB05`/`VB06`/`VB07`,
ближайшая группа во всей палитре) переписана без завязки на буквальный `#FFFFFF` —
после честного замера ни один артикул в него больше не попадает.
