## Зачем

Картон 40×40 см в масштабе 1:1 на A4 не влезает. Сейчас на выходе один PNG с `pHYs`
(`Core/Rendering/PngMetadata.cs`), резать и склеивать — руками, а масштаб при печати
зависит от просмотрщика. Нужен готовый к печати многостраничный PDF: страница = лист A4,
картинка нарезана с перекрытием, метками совмещения и подписью листа, масштаб 1:1 зашит
в PDF и от просмотрщика не зависит.

20×20 см влезает на A4 целиком, поэтому пункт «не горит» — но обратный набор `gull-2`
(п. 21) уже печатается 1:1, а панно 40×40 из рабочих ориентиров без склейки не напечатать.

## Границы (YAGNI)

- **Только A4.** Формат бумаги, поле принтера и ширину перекрытия в форму не выносим —
  инструмент для себя, «убрать параметр, а не сделать настраиваемым». Константы в одном
  месте (`SheetTiling`).
- **Только веб.** Диагностический стенд продолжает отдавать один PNG: приёмку смотрят
  глазами по цельному картону, нарезка там мешает.
- **Картон и схема, легенду не трогаем** — она лист A4 и так, отдельным листом
  (`CartoonLegend`).
- Панно, влезающее в один A4, всё равно отдаётся 1-страничным PDF — единообразие кнопки.
- PDF генерится на лету, не кэшируется в temp-хранилище.

## Архитектура

Три куска, по образцу связки `CartoonSheet` (чистая геометрия) → `SkiaMosaicRenderer`
(графика): считаем раскладку листов без Skia, потом рисуем.

### 1. `Core/Rendering/SheetTiling.cs` — геометрия, без графики

```
public sealed record SheetTiling
{
    public required IReadOnlyList<SheetTile> Tiles { get; init; }
    public required int Columns { get; init; }
    public required int Rows { get; init; }
    public required bool Landscape { get; init; }   // ориентация листа A4

    public static SheetTiling Plan(int sourceWidthPx, int sourceHeightPx, double pixelsPerMm);
}

public sealed record SheetTile
{
    public required int Row { get; init; }          // 1..Rows,  сверху вниз
    public required int Col { get; init; }          // 1..Columns, слева направо
    public required RectI SourceRectPx { get; init; }   // кусок исходного растра
    public required RectD PlacedMm { get; init; }       // куда лечь на листе, мм от угла листа
    public required RectD TrimMm { get; init; }         // обрезной прямоугольник (линия реза), мм
}
```

Константы (private const, мм):

| | значение | смысл |
|---|---|---|
| `PaperShortMm` / `PaperLongMm` | 210 / 297 | A4 |
| `PrinterMarginMm` | 8 | непечатаемое поле бытового принтера |
| `OverlapMm` | 12 | нахлёст соседних листов под склейку |

Печатное поле листа = `Paper − 2·PrinterMargin`. Шаг сетки = печатное поле − `Overlap`.
Число столбцов = `ceil((W_mm − Overlap) / step_w)`, аналогично строки.

**Выбор ориентации.** Считаем число листов для portrait и для landscape, берём меньшее;
при равенстве — portrait. Единственная развилка в этом файле.

**Инварианты (их же проверяют тесты):**
- объединение `SourceRectPx` покрывает весь исходный растр без щелей;
- соседние по горизонтали `SourceRectPx` перекрываются ровно на `round(Overlap · ppm)` px
  (по вертикали — так же);
- `TrimMm` каждого листа лежит внутри его `PlacedMm`;
- крайние листы могут быть уже полного поля (последний столбец/строка) — `PlacedMm`
  и `SourceRectPx` обрезаны по картинке, лишней белой каймы на листе нет.

`RectI` — новый маленький value-тип рядом с `RectD`/`PointD` (`Core/Rendering/`), если
подходящего нет; проверить перед добавлением.

### 2. `Core/Skia/SkiaPdfTiler.cs` — рендер PDF

```
public static byte[] Render(byte[] sourcePng, string sheetKindLabel);
```

- `SKBitmap.Decode(sourcePng)` — исходный растр; `PngMetadata.ReadPhysicalScale` → px/мм.
  Если pHYs нет — бросаем (все наши PNG его несут; молча печатать в неверном масштабе хуже).
- `SheetTiling.Plan(bitmap.Width, bitmap.Height, ppm)`.
- `SKDocument.CreatePdf(stream)`; размер страницы в пунктах (1 pt = 1/72"), из мм:
  `pt = mm / 25.4 * 72`. Страница всегда полный лист A4 в выбранной ориентации.
- На страницу:
  1. кусок растра `SourceRectPx` → `PlacedMm`, переведённые в пункты, с
     `SKSamplingOptions` высокого качества; масштаб выводится из ppm, не из «вписать» —
     1 мм бумаги = 1 мм натуры;
  2. Г-образные метки реза в четырёх углах `TrimMm`, штрих ~6 мм, выходят в поле листа;
  3. пунктир по тем сторонам `TrimMm`, где есть сосед (линия реза: этот лист режем по
     ней и кладём поверх соседнего);
  4. нижнее поле листа: «`{sheetKindLabel}` — лист R{Row}·C{Col} из {Rows}×{Columns} —
     верх ↑» + горизонтальная линейка-контроль 50 мм с подписью.
- Шрифт — тот же встроенный `SchemeFont.Typeface`, что в рендере схемы.

`sheetKindLabel` = «Картон» / «Схема». Легенда не зеркалится и не нарезается — сюда
не приходит.

Взаимодействие с п. 21 (обратный набор): когда появится зеркальный вывод, зеркалится
исходный растр до нарезки — `SkiaPdfTiler` уже получит отражённый PNG и номера листов
лягут правильно. Отдельной поддержки здесь не требуется, отметить в п. 21.

### 3. Web: эндпоинты + кнопка

- `IMosaicRenderer` не трогаем — тайлер статический, работает с готовыми байтами.
- `MosaicController`:
  ```
  [HttpGet("result/{id}/cartoon.pdf")]
  public IActionResult CartoonPdf(string id, int? c = null)

  [HttpGet("result/{id}/scheme.pdf")]
  public IActionResult SchemePdf(string id)
  ```
  Источник байт — тот же, что у `Cartoon`/`Scheme`: `results.ReadLadderCartoon(id, c)`
  с откатом на `results.ReadImage(id, ResultImage.Cartoon)`; для схемы —
  `ReadImage(id, ResultImage.Scheme)`. `File(pdf, "application/pdf", "karton-a4.pdf")`.
  `null` на источнике → `NotFound()`.
- `Views/Mosaic/Result.cshtml`: в `tabpanel__bar` вкладок «Картон» и «Схема» — ссылка
  «Печать A4 (PDF)» рядом со «Скачать PNG». На вкладке «Картон» URL учитывает текущий
  выбор цветов (`data-color-step` уже гоняет `c` для PNG — добавить параллельный
  `data-pdf-url`, или просто отдельная ссылка на дефолтное число цветов; уточнить в коде,
  минимально — вторая ссылка без `c`, картон печатают на финальном числе).
