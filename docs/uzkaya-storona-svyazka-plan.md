# Узкая сторона куска: свести две мерки (TODO п. 8)

## Зачем

TODO п. 8: `minSideP5` (стенд, вдоль оси курса) даёт p5 = 4,7–6,0 мм; прежний разовый
скрипт по кратчайшей ширине полигона — p1 = 4,0–4,5 мм. Непонятно, какая мерка говорит
про руку мастера (порог узкой стороны с натуры — 5 мм). Свести.

## Что сделано

1. **`Metrics.cs`** — добавлена `MinWidth(polygon)`: для каждого ребра проекция всех вершин
   на его нормаль, span; минимум по рёбрам (опора / rotating calipers). Для выпуклого
   полигона направление минимальной ширины всегда перпендикулярно ребру, так что это точно;
   для лёгкой вогнутости резаного куска — близкая верхняя граница. Не привязана к оси курса.
2. Колонки стенда: `minWidthP5`, `minWidthP1`, `narrowWidth` (доля кусков < 5 мм по истинной
   ширине). Verbose-строка печатает `ширина p5 .. p1 ..` и `узких<5мм ..`.
3. Прогон по всем `samples/` × {21×21, A4, 40×40} × 12 цветов → `diag-out/p8/`.

## Результат

30 строк. Медианы: `minSideP5` 4,93 (4,60–5,96); `minWidthP5` 4,65 (4,41–5,61);
`minWidthP1` 4,29 (4,23–5,16); `narrowWidth` 11,7 % (0,6–19,9); `awkward` 5,7 % (0,6–11,8).

- Прежние 4,0–4,5 мм воспроизводятся: `minWidthP1` ≈ 4,23–4,29 почти на каждом фото и размере.
  Мерка не была артефактом старого набора.
- Расхождение с `minSideP5` (~0,3 мм на p5) — геометрия: кусок под углом к курсу узок по
  диагонали, а `Extent` вдоль оси курса её не видит.
- Руку описывает **истинная ширина**: кусачки бьют по фактической самой узкой хорде.
  Воротная мерка → `minWidthP5` / `minWidthP1`.
- `minWidthP1` ≈ 4,2 мм == `floorAcross = across*0,6` (`Tessellation.cs:115`). Флор слияния
  слайверов намеренно ниже 5 мм (комментарий там же). Хвост p1 — сам флор, не протечка.

## Что не делаем

Отдельного фикса нет: узкие куски на картоне — клинья на стыках курсов, ведутся в п. 4 и
`forma-kuska-plan.md`. Если порог 5 мм понадобится соблюдать — поднять `floorAcross` к
`across*0,72` и/или мерить флор истинной шириной; цена — короче ряды; отдельный план + приёмка.
