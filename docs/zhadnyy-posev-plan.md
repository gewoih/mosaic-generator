### Как работает `Drain` сейчас

`StreamlinePlacer.Drain` (`Tessellation.cs`):

```
пока очередь семян не пуста:
    семя = очередь.Dequeue()
    если семя занято/снаружи → пропустить
    курс = Integrate(семя)                 ← сразу трассируем
    если курс короче minLength → пропустить
    зарегистрировать курс как барьер       ← сразу коммитим
    разбросать новые семена по бокам курса
```

Порядок обхода — FIFO. Первое дошедшее до места семя занимает его насовсем, даже если из
соседнего семени вышел бы вдвое более длинный пробег через ту же точку. Линии тормозят друг
о друга (`TooClose` — 98 % обрывов), поле набирается россыпью коротких курсов, между их
несошедшимися концами остаются клинья — а клин это и филлер, и зажатая со многих сторон
ячейка Вороного (5–6 вершин).

## Что делать

### Отбор кандидатов (priority-variant Jobard–Lefèvre)

Меняется только цикл `Drain` для заливки. Структурные проходы — бордюр (шаг 1) и контурные
курсы (шаг 2) — не трогаются: они кладутся барьерами до всякой заливки, порядок там задан
геометрией, а не очередью. Второй проход `Drain` с порогом `minLength * 0,5` и зарастание
дыр (`Trace`) на первом заходе оставляю как есть — перемеряю после и правлю отдельно, если
понадобится.

Новый цикл:

```
пока есть живые семена:
    кандидаты = []
    для каждого живого семени из текущей пачки:
        курс = Integrate(семя)             ← трассируем БЕЗ регистрации
        если курс >= minLength: кандидаты.add((длина, курс, семя))
    если кандидатов нет → выход
    выбрать кандидата с наибольшей длиной
    зарегистрировать его курс как барьер
    разбросать новые семена по бокам этого курса
    семёна проигравших кандидатов вернуть в очередь  ← перепроверятся против нового барьера
```

«Пачка» — все семена, доступные на данный момент (снятые с очереди за один проход). Проигравшие
возвращаются и на следующем шаге трассируются заново уже с учётом только что уложенной линии:
если новый барьер их перекрыл — они отсеются по `Inside`/`TooClose`, если нет — снова пойдут
в конкурс. Это стандартная поправка: класть всегда самый длинный из доступных пробегов, а не
первый попавшийся.

**Стоимость.** Каждое выжившее семя трассируется по разу за раунд, в котором участвует.
Панно рабочих размеров дают 200–500 обрывов и десятки-сотни курсов; трассировка — сотни шагов
Эйлера. Даже квадратичный худший случай (все семена доживают до конца) — это доли секунды на
15×15 и секунды на 60×60. Если 60×60 начнёт заметно тормозить — ограничу пачку первыми `K`
семенами (`K` порядка 32), тогда сложность линейна по числу семян. Решу по факту замера времени,
которое стенд печатает в каждой строке.

**Детерминизм.** При равной длине кандидатов побеждает первый по порядку снятия с очереди —
порядок посева уже детерминирован. Тест `TheTessellationIsDeterministic` должен остаться
зелёным.

### Почему это должно помочь трём метрикам сразу

- **Обрубки.** Самый длинный кандидат по определению не короткий. Короткие курсы остаются
  только там, где ни одно семя не дало длинного пробега, — то есть где место физически тесное.
- **Филлеры и многогранники.** Длинный курс проходит промежуток насквозь, а не утыкается в
  середину; сходящихся концов меньше, клиньев между ними меньше, а клин — это и есть филлер и
  зажатая ячейка.

Всё это — гипотеза. Проверяю по факту (ниже).

## Как понять, что получилось

Замер тем же прогоном по восьми фото, четыре размера. Критерии приёмки из TODO:

1. **Доля курсов короче трёх кусков ниже 15 %** — на приоритетном 15×15 и в среднем.
2. **Доля филлеров не растёт с размером панно** — сравнение 15×15 против 60×60 по каждому фото.
3. **Доля 5- и 6-гранников ниже 15 % суммарно.** Реалистичный прогноз — не дотянет: часть
   многогранников рождается разрезкой Вороного зажатой ячейки, а не порядком посева. По
   решению от 2026-09-03 адресную правку разрезки в этом пункте **не делаем** — если метрика
   осталась выше 15 %, это записывается как предел метода, отдельный вопрос не открывается.
4. **Медиана длины курса под куском (p50) не ухудшается** — стенд её печатает.

Не должны вырасти: `bareR` (наибольшая голая окружность — это пункт 5, у него своя причина,
но и портить нельзя), `awkward`, `uncuttable`, `minSideP5`, `overlap`, `structureOff`.
ΔE от геометрии не зависит, но держу в поле зрения.

Плюс просмотр превью глазами на 15×15 и 30×30 (gull, dolphin, landscape): курсы должны читаться
длиннее, клиньев в фоне меньше, спиралей у медиальной оси нет.

**Если пункт не приводит к улучшению картона — фиксирую это в разделе «Что вышло» и откатываю
правку.**

# Что вышло

**Отбор кандидатов картон не улучшает. Правка откачена.**

Реализовал priority-вариант в `StreamlinePlacer.Drain` (пачка семян → трассировка всех без
регистрации → кладём самый длинный → проигравших назад в очередь). Прогнал тем же сбором по
восьми фото, четыре размера. Средние по восьми фото, база → после:

| размер | курсов <3 кусков | филлеров | 5+6-гранники | медиана курса под куском | время 60×60 |
|---|---|---|---|---|---|
| 15×15 | 28,8 % → **30,5 %** | 10,5 % → 10,1 % | 35,7 % → 33,3 % | 15,2 → 21,0 | — |
| A4 | 26,2 % → 24,6 % | 7,5 % → 6,6 % | 34,0 % → 33,2 % | 18,0 → 19,0 | — |
| 30×30 | 25,0 % → 24,5 % | 7,1 % → 7,1 % | 29,6 % → 28,6 % | 23,4 → 29,4 | — |
| 60×60 | 17,0 % → 15,2 % | 9,9 % → 9,4 % | 51,0 % → 52,8 % | 37,5 → 39,2 | 2,0 с → **4,8 с** |

- **Обрубки.** На приоритетном 15×15 стало *хуже* (28,8 → 30,5 %). На остальных размерах —
  сдвиг в пределах шума (менее 2 п.п.). Цели <15 % нет нигде, ни до, ни после.
- **Филлеры.** Не изменились и по-прежнему растут с размером панно (6 % на 15×15 → 9–14 % на
  60×60). Главное, ради чего затевалось, — не тронуто.
- **Многогранники.** Шум ±2 п.п. вокруг исходных 30–51 %. До 15 % не приблизилось.
- **Медиана курса** подросла (не ухудшение), но это единственный сдвинувшийся показатель, и он
  не входит в цели пункта.
- **Время** 60×60 выросло в 2,4 раза из-за повторной трассировки проигравших семян каждый раунд.

**Почему не сработало.** Семена заливки рождаются смещением уже уложенных курсов на `dSep`. В
одной пачке почти все кандидаты — это близкие почти-параллельные линии сопоставимой длины;
выбор «самого длинного» среди почти-дубликатов ничего не решает. Обрубки, клинья и зажатые
ячейки Вороного берутся из геометрии поля — медиальные оси форм, схождение эха контуров в
точку, теснота маленького панно, — а не из порядка обхода очереди. Предпосылка TODO («стандартная
поправка к Jobard–Lefèvre») на этом поле неверна.

**Что осталось в коде.** Только поправка устаревшего комментария в шапке `Advected`: причины
обрыва курса — 98–100 % проверка расстояния, кривизна и самопересечение почти не срабатывают.
Сам `Drain` возвращён к исходному виду побайтово.

**Что дальше по пункту 3.** Отбор кандидатов исчерпан. Если возвращаться к обрубкам/клиньям —
это правка не порядка посева, а либо разрезки Вороного зажатой ячейки (по решению от
2026-09-03 не трогаем), либо самого поля направлений в зонах схождения эха (пересекается с
пунктом 7). Отдельным заходом и с отдельным планом.
