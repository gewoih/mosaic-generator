# Обводка силуэта: замкнутое кольцо вместо семи фрагментов

Пункт 1 из [`TODO.md`](../TODO.md). Статус: **план, ждёт «поехали».**

Меряется стендом `tools/MosaicGenerator.Diag` по восьми фото из `samples/`,
размеры 15×15 / 21×29,7 / 30×30 / 60×60, `--levels Draft --colors 12`.

---

## 1. Что не так

Вокруг фигуры должно идти непрерывное кольцо в один-два ряда, повторяющее силуэт
(opus vermiculatum). Механизм есть — `Tessellation.Advected` шаг 2 кладёт два ряда
вдоль каждого контура, в них 5–11 % кусков. Но как обводка это не читается.

Стенд печатает длины контуров в модулях. Чайка 30×30:

```
контуров 7, длины в модулях: 30, 21, 20, 15, 13, 10 … (ещё 1)
```

Обвод птицы ≈ 85 модулей, самый длинный фрагмент — 30. Силуэт разорван на семь
кусков, ни один не обходит фигуру. По остальным семи фото так же: 10–16 контуров,
самый длинный 23–40 модулей.

**Почему рвётся.** `ContourSet.Extract` берёт линию уровня силы края (`field.EdgeCells`,
марширующие квадраты, порог `max(0.12, p99·0.42)`). Там, где тон крыла совпал с тоном
неба, перепада яркости нет, линия уровня обрывается. Глаз силуэт достраивает, градиент —
нет.

**Почему это важнее прочего.** Единственный оставшийся дефект, видимый на макете без
метрик: пользователь сравнил вывод с классической работой и первым делом спросил, где
обводка.

---

## 2. Диагноз: чего не хватает пайплайну

Весь верхний уровень — `ContourSet` → `CourseGuidance` (эхо фона) → `Tessellation`
шаг 2 (контурные курсы) — стоит на одном источнике: **линии уровня локального
градиента**. Локальный градиент — плохой детектор силуэта: он нулевой везде, где две
области сошлись по тону, а по контуру фигуры таких мест обычно несколько.

Нужен **второй, областной** сигнал: не «где резкий перепад», а «что здесь одна
связная область, а что другая». Областной сигнал замкнут по построению и не боится
локального совпадения тона — он интегрируется по площади.

Оба сигнала нужны вместе: заливка даёт замкнутость, край даёт точность (фронт заливки
на мягком градиенте размыт, край — нет).

---

## 3. Решение: `FigureMask`

Новый класс `src/MosaicGenerator.Core/Grid/FigureMask.cs`. Строится из `DirectionField`
(та же сетка `Width×Height`, ~6 ячеек на модуль) плюс поле яркости/цвета кадра.

### 3.1. Поле цвета

`DirectionField.SampleLuminance` уже делает ровно нужную выборку: `crop` →
`image.AverageLinear` → `ToLab().L` по сетке `Width×Height`. Расширяем: `DirectionField`
хранит и отдаёт **Lab-триплет** на клетку (`internal ReadOnlySpan<double> LabCells`,
три компонента), не только `L`. `edge` и тензор считаются как раньше по `L`.

Одна выборка вместо двух, ничего в существующих числах не двигается.

### 3.2. Заливка фона от рамки

1. Гистограмма ΔE клеток к среднему цвету рамки (одна ячейка вглубь по всему периметру).
2. Порог `tBg` — метод Отсу по этой гистограмме (разделяет «похоже на рамку» / «не
   похоже»). Без подбираемого числа: Отсу берёт порог из самих данных.
3. Заливка (BFS) от всех клеток рамки по 4-связности: клетка принадлежит фону, если
   ΔE к среднему фона (пересчитываемому по мере роста) `< tBg`. На мягком градиенте
   неба локальный шаг мал → заливка идёт; на крыле шаг велик → стоп.
4. `background` — булева маска. `figure = !background`.

### 3.3. Связные компоненты и выбор фигуры

- Связные компоненты `figure` по 4-связности.
- Отсекаем компоненты площадью `< 2 %` панно (перо, блик — им остаётся собственный
  контурный курс, см. §4).
- Остаток — 1–3 «фигуры». Обычно одна.

### 3.4. Уточнение границы краем

Для каждой фигуры: обход внешней границы маски марширующими квадратами по залитой
`figure` (0/1) → один замкнутый полигон. Затем **притягиваем** вершины полигона к
ближайшему длинному краевому фрагменту `ContourSet` в пределах `1.5·модуль`: там, где
край есть, кольцо садится точно на него; там, где края нет (тональный разрыв) — идёт
по фронту заливки. Дуглас — Пекер с `epsilon = 0.75·модуль`, как в `ContourSet`.

### 3.5. Откаты (кадр без выраженной фигуры)

`FigureMask.HasFigure == false`, если любое:

- фон занял `> 92 %` панно (нет объекта — ровный кадр, текстура);
- ни одна компонента фигуры не прошла порог 2 %;
- крупнейшая фигура касается `≥ 3` краёв панно (заливка потекла — контровый силуэт,
  край утоплен в засветке);

В этом случае `ContourSet`/`CourseGuidance`/`Tessellation` работают **ровно как
сейчас** — пункт для таких кадров ничего не меняет. Это пейзаж, портрет на 15×15,
кадр без объекта: они уже мерятся приемлемо, трогать нельзя.

## 4. Как встраивается

### 4.1. `ContourSet.Extract` → замкнутое кольцо первым

Новая перегрузка `Extract(field, ..., FigureMask? mask)`:

- если `mask?.HasFigure == true` — список контуров = `[кольцо каждой фигуры (замкнутое),
  затем длинные краевые фрагменты, НЕ совпавшие с кольцом]`. Кольца идут первыми
  (сортировка по длине их и так поставит вперёд — они длиннее фрагментов).
- иначе — сегодняшний код без изменений.

Внутренние кромки (перо, глаз, клюв) остаются в списке как открытые фрагменты и
по-прежнему получают контурные курсы — внутреннее андаменто фигуры от этого только
богаче.

### 4.2. `CourseGuidance.Build` — эхо по кольцу

`steering` = кольца фигур (если есть), иначе сегодняшний фильтр по длине. Кольцо
длиннее `steeringMin` всегда, так что фон получает чистое эхо силуэта, а не эхо
самого длинного обломка.

### 4.3. `Tessellation.Advected` шаг 2 — оба ряда снаружи

Сейчас `offset ∈ { −dAcross/2, +dAcross/2 }` — один ряд внутрь фигуры, один наружу.
Ряд внутрь переписывает андаменто тела у края и сталкивается с линиями тела (обрубки,
питает пункты 3 и 5).

Для **замкнутого кольца фигуры**: оба ряда наружу, `offset ∈ { +dAcross/2,
+3·dAcross/2 }`, где «+» — сторона фона (определяется по `FigureMask`: знак нормали,
смотрящей в клетку `background`). Фигура сохраняет собственное андаменто, фон получает
ореол в два ряда — классический opus vermiculatum.

Для открытых внутренних фрагментов — седлающая раскладка как сейчас (у них нет
осмысленного «снаружи»).

`OffsetPolyline` с замкнутым полигоном уже работает (проверено: в точке смыкания
односторонняя нормаль, шов на один модуль — приемлемо). `AddSites` замкнутый курс
тоже уже обрабатывает (`closed` на строке 322).

## 6. Тесты

`tests/…/Grid/FigureMaskTests.cs` (новый):

- диск на контрастном фоне → одна фигура, кольцо замкнуто, длина ≈ периметру диска;
- диск, у которого четверть границы совпадает по тону с фоном (тональный разрыв) →
  кольцо всё равно замкнуто, длина в пределах 10 % от периметра;
- ровный кадр (без фигуры) → `HasFigure == false`;
- кадр, где «фон» связан через всю фигуру (заливка течёт) → `HasFigure == false`;
- детерминизм: повтор даёт ту же маску побитово.

`tests/…/Grid/ContourSetTests.cs`, `TessellationTests.cs`:

- с `FigureMask` замкнутого диска: самый длинный контур ≥ 0,8·периметр (регресс: со
  старым поведением падает — там он ~0,35·периметр);
- контурные курсы кольца лежат оба со стороны фона (ни одного центра куска внутри
  маски фигуры дальше `dAcross` от границы).

## 7. Проверка на живых фото

```bash
for f in samples/*.jpg; do
  dotnet run -c Release --project tools/MosaicGenerator.Diag -- \
    --photo "$f" --out diag-out/$(basename "$f" .jpg) \
    --sizes 15x15,21x29.7,30x30,60x60 --levels Draft --colors 12 --gamut
done
```

Критерии приёмки:

- **Главный.** Длина самого длинного контура сравнима с обводом фигуры: для чайки
  30×30 — порядка 70–85 модулей вместо 30. На ≥ 5 из 8 фото появляется замкнутое
  кольцо. **Если меньше 5 — пункт не улучшает картон, сообщаю это и откатываю.**
- Глазами на 30×30 и 60×60: вокруг фигуры читается непрерывное кольцо в два ряда,
  фигура сохраняет своё андаменто.
- Не ухудшить: медиана длины курса под куском, доля обрубков (пункт 3), доля заплаток,
  `structureOff`, геометрия щелей (пункт 5) — в пределах шума на всех восьми фото.
  Кадры без фигуры (`landscape*`, портрет 15×15) — раскладка побайтово прежняя.
- Детерминизм: повтор даёт те же байты PNG.

## 8. Что НЕ делаем в этом заходе

- Пункт 2 (бордюр по доле площади), пункт 3 (жадный посев), пункт 5 (щели) — отдельно.
- `FigureMask` для взвешивания палитры по важности (пункт 8) — маска пригодится, но
  это другой заход.
- Никаких подбираемых порогов: `tBg` из Отсу, площадь 2 %, касание 3 краёв, `92 %` —
  фиксированные структурные константы, не настройки формы.
