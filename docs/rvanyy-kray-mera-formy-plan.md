# Пункт 22, шаг 1: мера формы рваного края

Пункт 22 бэклога: `banding` меряет **факт** тонального разрыва (пара соседей, которым фото
даёт почти один цвет, а палитра — разные), но не его **форму**. Аккуратная прямая граница
между двумя ступенями и рваная зубчатая клякса дают `banding` один и тот же счёт. На картоне
это разные вещи: первое — законный приём мастера, второе — грязное пятно в чистом небе.

Сам пункт велит: **сначала мера формы, потом правка подбора**. Этот план — только про меру
и её замер. Правка `Quantizer` / `CoherentMap` / `CellSmoother` — отдельный план после того,
как число снято по всем кадрам и закреплено в базе.

## Что меряем

**Извилистость границы между артикулами на тех участках, где фотография гладкая.**

Не «извилистость любой границы»: на настоящем крае сюжета (клюв чайки, очки на лице, стебель
мака) зубчатая граница — норма, там кусок 6 мм честно обходит контур. Дефект — только там, где
опоры в картинке нет. Критерий «опоры нет» берём тот же, что у `banding`: фото-ΔE между
соседями < 2. Это делает новую метрику **парной к `banding` по построению** — тот же набор
пар, тот же порог, — и настоящие края сюжета отсекаются сами (там фото-ΔE большой).

### Носитель — пиксельный растр клеток

Тессеры — адвектированные многоугольники неправильной формы; общей длины ребра между двумя
соседними тессерами в данных нет, только расстояние между центроидами. Граница области и её
периметр чисто определяются лишь на растре. Берём растеризацию как в `CoverageMask.Rasterise`
(точка-в-многоугольнике по сетке `ModuleWidthMm / K`, `K ≈ 6…8`), но в каждый пиксель кладём
**индекс артикула** владеющей тессеры, а не флаг покрытия. Сосед-пиксель другого артикула —
граничный пиксель; пара артикулов (a, b) на нём — граничная пара.

### Формула — извилость, а не вытянутость

Вытянутая, но прямая лента неба (законная тональная ступень) не должна штрафоваться. Поэтому
нормируем **не на корень из площади** (тогда лента даёт высокое число просто из-за формы), а
на прямой ход границы:

1. Собрать граничные пиксели в полилинии (обход контура marching-squares по растру артикулов).
2. Для каждого звена полилинии проверить опору: фото-ΔE между артикулами по разные стороны
   < 2 → звено «без опоры». (Фото берём то же уплощённое, что видит подбор — `source` в
   `Program.cs`, снятое по клеткам.)
3. Метрика по полилинии без опоры длины `L` с хордой между концами `C`
   (или периметром выпуклой оболочки её точек `P_hull`):

   ```
   рвань = Σ (L − C)  по всем участкам без опоры
           ───────────────────────────────────────
           Σ L                по всем участкам без опоры
   ```

   Прямая ступень: `L ≈ C` → 0. Зубчатая клякса: `L` вдвое больше хода → 0,3…0,6.
   Знаменатель — только граница без опоры, поэтому кадр без тональных ступеней (мало таких
   границ) не даёт ложный ноль в числителе делением на большую общую длину.

**Запасной вариант, если сборка полилиний окажется хрупкой на растре:** плотность поворота —
Σ|угол поворота| вдоль участков без опоры на единицу их длины. Считается по цепочке граничных
пикселей без явной полилинии, устойчивее к дыркам растра. Рваный край — высокая плотность
поворота. Реализуем сначала основную; если marching-squares по растру артикулов даёт рваные
куски контура на швах — переключаемся на плотность поворота, это записываем в план по факту.

## Замер (способ перепроверки)

Прогон — стандартная процедура приёмки: 13 кадров из `samples/` × 3 размера (20×20, 30×30,
40×40), **откус 6 мм**, 15 цветов, 39 прогонов. Снять базу метрики этим прогоном, занести
медиану / p90 / max в таблицу базы.

**Метрика верна, если:**

- `sunset` 40×40 — почти **0**. Контроль: плоское поле, курсы прямые и параллельные, рваных
  границ в сюжете нет. Если тут не ноль — метрика меряет вытянутость или структуру курса, а
  не рвань; вернуться к формуле.
- `gull` (небо — ровный градиент без объектов, на картоне тёмное пятно с зубчатым краем),
  `landscape` (небо полосами со ступенчатым краем), `sailboat` (небо в ленты со ступенчатым
  краем, `banding` 0,061–0,080 — верх набора) — **высокие** значения, верх набора.
- `poppy` (край лепестка), `gull` (клюв), `human` (очки, борода) — метрика их **не** поднимает:
  это настоящие края сюжета, фото-ΔE там большой, звенья идут «с опорой». Проверяется глазами
  по карте `--ragged`: подсвеченная граница должна лежать в небе/воде, а не по контуру объекта.
- Геометрия побитово не двинулась: метрика read-only, добавляется колонкой. `max |Δ|` = 0 по
  всем геометрическим колонкам (ранний гейт из базы приёмки) — заодно подтверждает, что новый
  код не залез в пайплайн.

**Рукотворные кадры (зеркало пункта 22, не ворота):** на `sailboat` / `architecture` /
`geometry` дефект края виден глазами — `ragged` при этом должен быть заметно выше медианы,
а `banding` — оставаться в норме базы (форма и факт — разные оси).

## Как реализовано (по факту)

`tools/MosaicGenerator.Diag/RaggedBoundary.cs`, колонка `ragged` в `metrics.csv` рядом с
`banding`/`merged`, флаг `--ragged` → PNG-карта, строка «рвань» в консоль.

Два отступления от плана, найденные на прогоне:

1. **Заливка шва.** Между соседними тессерами шов оставляет 1–2 пустых пикселя, и восточный
   сосед закрашенного пикселя почти всегда пустой, а не другой артикул — граница не находилась
   вовсе (карта пустая). Правка: многоисточниковый BFS заливает каждый пустой пиксель ближайшей
   тессерой, после чего две ступени сходятся.
2. **Мера — плотность поворота, не `(L−C)/L`.** Основную формулу плана добил растровый диагональ:
   прямая наклонная ступень на растре идёт лесенкой, `L−C` у неё большой. Взята запасная из
   плана: средний модуль поворота границы на модуль длины **после упрощения Дугласа–Пекера с
   допуском 2 модуля**. Наклонная монотонная лесенка упрощается в один отрезок → 0; рваная
   клякса остаётся рваной → высокое число. Порог 2 модуля — в константе `SimplifyModules`.

**Проверка глазами прошла (карты `--ragged`, 40×40):**

- `sunset` — **0,00**. Контроль держит.
- `gull` — **0,13**. Красным — рваная тональная ступень в гладком небе поверху и пятно слева;
  силуэт птицы обведён **серым** (с опорой), в счёт не идёт. Ровно дефект пункта 22.
- `sailboat` — 0,10, `landscape` — 0,00 (небо в этом рендере не порвано, границы с опорой),
  `poppy` — 0,08. Полная база — прогоном приёмки.

## Что этот план НЕ делает

- Не трогает `Quantizer`, `CoherentMap`, `CellSmoother`, `PaletteReducer` — ни строки.
- Не гонит `banding` вниз. Она парная с `merged`; обнуление любой ломает другую.
- Не вводит ворота по `ragged`. Сначала — число по всем кадрам, потом отдельный разговор,
  что оно ловит и где его порог.
- Не отбирает границы по `|∇|` фото — ровно тот механизм, что делил плавные градиенты на
  ложные горизонтальные полосы (`docs/zony-i-granitsy-plan.md`). Опора звена — по фото-ΔE
  между уже назначенными артикулами, как у `banding`, а не по силе градиента.
